# Testing on a real Home Assistant OS installation

Status in the cloud environment — unrun. The local test uses the add-on image and a mock Supervisor that supplies user identity, the TCP peer address and a variable Ingress prefix.

1. Add the repository to Supervisor, install OpenSOHO, enable **Show in sidebar** and start it with a random secret. Check the default security settings and logs. On each architecture, verify add-on startup and startup after a host reboot.
2. As an administrator, open the panel from the sidebar using the local address, then the external HTTPS domain. Verify automatic login, navigation, reload, the device list, dashboard and JS, CSS and API requests under the current Ingress prefix. Check for mixed content. Open an SSE connection through the SDK and verify event delivery when a device record changes. PocketBase uses SSE for realtime.
3. Use a regular account in a separate browser profile. Verify that the sidebar panel is hidden and access to both the panel URL and session endpoint is denied. Repeat with a signed-out profile. From the LAN port, verify that the panel and HA session endpoint are denied even with Ingress headers. Create an `api_users` account in the Ingress panel and use its native password and token on the LAN port to authenticate and read device status.
4. Sign in as an administrator. Check that the UI has no PocketBase token. Sign out of HA, open the previous Ingress URL in another tab and record behavior before and after the Ingress cookie expires or is removed. Sign in again and verify access under the correct role. Repeat with an account whose administrator role was revoked. Check how your Supervisor version refreshes cached roles.
5. Register the physical routers. Verify monitoring and, after the operator approves the configuration, verify configuration download and application. Confirm internet access, LAN, DHCP, roaming and connectivity to HA and the controller.
6. Record device IDs, current configuration, the port and monitoring reports. Restart the add-on, create a cold backup, update the image and verify the same state after the update. Restore the backup in a safe test instance and confirm that routers can connect to the restored controller.
